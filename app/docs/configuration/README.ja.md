# 設定リファレンス

[English](README.md)

設定はすべて `config/` にあります。deploy する内容を変えるために、ほかのファイルを編集する必要はありません。

| ドキュメント | 対象 |
|---|---|
| [common.ja.md](common.ja.md) | 環境、アカウント、機能の切り替え、VPN の接続、命名、アドレスの割り当て、認証情報と秘密の値（`.env.<環境名>`） |
| [aws.ja.md](aws.ja.md) | `config/aws/` |
| [google.ja.md](google.ja.md) | `config/google/` |
| [azure.ja.md](azure.ja.md) | `config/azure/` |

## 表の読み方

| 列 | 意味 |
|---|---|
| 項目名 | 設定ファイルに書くプロパティの名前 |
| 設定する内容 | その設定が何をするか |
| 設定できる値 | 型、または受け付ける値。`string`、`number`、`boolean` は TypeScript の型 |
| 指定がない場合のデフォルト値 | 項目を省略したときに使われる値。**必須** は必ず指定が必要という意味。`—` は省略するとその機能を使わないという意味 |
| 備考 | 制約、ほかのファイルとの関係、値を変えたときの影響 |

## すべての設定ファイルに共通の決まり

| 決まり | 内容 |
|---|---|
| `build: true / false` | 一覧の項目（VM、DB、ロードバランサー、コンテナのサービスなど）は、`build` が `true` のときだけ作られます。後で有効にするために、`build: false` のまま項目を残しておけます（例: stg に一時的にインスタンスを追加する）。`build: false` の項目は作られず、ほかの設定との整合性も確認されません |
| `byEnv({...})` | 環境（`dev`、`stg`、`prod`）ごとの値を書きます。[common.ja.md](common.ja.md#環境) を参照 |
| `name` | クラウド上のリソースの実際の名前。省略できる項目で省略すると、既定の名前 `<PROJECT_NAME>-<cloud>-<リソースの種類>[-<key>]` が作られます（[common.ja.md](common.ja.md#命名) を参照） |
| `key` | 任意。リソースの Terraform のアドレス（construct ID）を固定します。既定は `name`。リソースを作り直さずに名前を変えるときは、`key` に**古い**名前を書きます |
| 名前での参照 | サブネット、セキュリティグループ、IAM ロール、ロググループ、ターゲットグループなどは、`name`（または `key`）で参照します。存在しない名前があると、synth がエラーで止まります |
| 秘密の値 | コミットしてはいけない値は、環境変数（`process.env.X`）から読みます。`.env.<環境名>` に書きます |
| 機能 | 機能をそもそも作るかどうかは、`config/commonsettings.ts`（`clouds.<cloud>.features`）で決めます。機能ごとの設定ファイルは、その機能が有効なときだけ読まれます |

## 名前の書き方

リソースの実際の名前の書き方は、リソースの種類によって違います。どれに当たるかは、各表に書いてあります。

| パターン | 対象 | 意味 |
|---|---|---|
| `name` のみ | AWS のリソース、VM、ほとんどの最上位のリソース | `name` が実際の名前で、参照にも使います |
| `name` + `resourceName` | Google Cloud の VPC、サブネット、ファイアウォールルール、プロキシ専用サブネット。Azure のサブネット。AWS の EFS のアクセスポイント | `name` はほかのファイルから参照するための論理名、`resourceName` がクラウド上の実際の名前です。`resourceName` を省略すると既定の名前が作られます（Azure のサブネット: `<PROJECT_NAME>-azure-subnet-<name>`） |
| `names: { ... }` | RDS / Aurora、Azure Files、ACR、Key Vault、Application Gateway、Cloud Load Balancing | 1 つのリソースのために作るサブリソース（サブネットグループ、プライベートエンドポイント、リスナーなど）の実際の名前。省略した項目は既定の名前になります |
| `<対象>Names: [...]` / `{ <キー>: 名前 }` | VPN（カスタマーゲートウェイ、トンネル、接続）、DNS の転送ルール、Google のログの経路 | 順番どおり（トンネルやゲートウェイごとに 1 つ）、またはキー（ドメイン、経路）ごとに名前を並べます。省略した項目は既定の名前になります |

実際の名前を変えると、リソースは作り直されます。名前を変えても Terraform のアドレスを変えたくない場合は、`key` に古い値を書きます（上記を参照）。
